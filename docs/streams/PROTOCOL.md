Two Claude Code sessions work on this repository at the same time. This file is the full set of
rules; `D-355` created the streams and `D-357` extends it with this protocol. Read it together
with your own status file, `docs/streams/A.md` or `docs/streams/B.md`.

## 1. One folder, one session (D-357 (1))

- Each session works **only in its own folder** and **never runs git in the other one**. A
  worktree shares the object store: a `git checkout`, `rebase` or `branch -D` run from the wrong
  folder can move or delete the other stream's branch under its feet.
- **Every new branch carries its stream's prefix**, `a/` or `b/`, and has exactly **one owner**.
  Branches created before this protocol are **grandfathered**: they keep their names and are not
  checked.
- **The streams connect only through `main`.** Never merge or cherry-pick from the other
  stream's branch; wait for it to reach `main`.

## 2. Path ownership (D-357 (2))

The machine-readable list is `docs/streams/ownership.yaml`; the CI guard enforces it.

**Stream A only** — a stream-B need for any of these is a **P- question**, not an edit:
`HANDOFF.md`, `CLAUDE.md`, `docs/STANDING_PROMPT.md`, `.github/`, `pyproject.toml`, `uv.lock`,
the Alembic migrations, and (until T11 is merged) `src/strategy_factory/components/`.
Changing any of them also needs a **notice to the supervisor** in the PR body.

**Split ownership:**
- `configs/universe/` (the symbol lists, `symbol_changes.csv`) is **stream B's**;
- `configs/universe.yaml` is **stream A's**, regenerated by A with `sfac universe generate`
  after a stream-B merge (**D-394**). Stream B lists every symbol it adds or removes in
  `docs/streams/B.md` so A can regenerate.

**Append-only, per your own ID range:** `docs/decisions/decisions_log.md` and
`docs/decisions/pending.md`. Never edit or renumber another stream's row. A conflict in either
file is resolved by **keeping every row in ID order**, one row per ID; when the same ID appears
twice, the more resolved version wins (answered beats open; the higher `D-` number wins).

Everything not listed is **shared**: `docs/tasks/`, `docs/reviews/`, `docs/adr/`, `tests/`,
`scripts/`, the rest of `src/` and the rest of `configs/`.

## 3. Rebase and merge (D-357 (3))

1. **Every task starts with `git fetch origin` and a rebase onto `origin/main`.**
2. **Merges are one at a time.** Immediately before a merge, rebase onto the **latest** `main`
   and let CI go green; merge only on "Approved. Merge …" (D-401).
3. **After a merge, the other stream rebases** onto the new `main` before continuing.
4. Critical tasks still stop after their review and wait for "Approved" (D-402).

## 4. CI guards (D-357 (4))

`sfac streams check` runs in CI on every branch and fails the build when:

1. **Path ownership** — an `a/` or `b/` branch changes a path owned by the other stream.
2. **ID discipline** — a `D-` or `P-` row added by this branch is a duplicate, or falls outside
   the adding stream's range. (Rows added by an unprefixed, grandfathered branch are only
   checked for duplicates.)
3. **A single Alembic head** — the migration graph must have exactly one head, so two streams
   cannot both add a migration.

Run it locally the same way:

```bash
uv run sfac streams check --base origin/main
```

## 5. Session start (D-357 (5))

At the start of every session, check that the folder and the branch match the stream:

```bash
git worktree list
git branch --show-current
```

If the current worktree is not this stream's folder, or the branch carries the other stream's
prefix, **stop and report** — do not "fix" it by switching branches.

**No stream starts work until the supervisor confirms its setup.**
