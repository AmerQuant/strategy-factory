| P-36 | The `auto` split of cores between processes and Numba threads | T10b, D-334. The decision fixes only the product bound `workers x numba_threads <= cpu_count`. `configs/pipeline/executor.yaml` defaults both to `auto`, and the executor resolves them: both auto → `workers = floor(sqrt(cpu))`, `numba_threads = cpu // workers`; one given → the other is `max(1, cpu // given)`; both given and over the bound → refused. On the 20-core development machine that is 4 workers x 5 threads, which is also the fastest row of the scalability benchmark (1.43 s vs 1.80 s for the best single-thread row). | Confirm the rule, or set explicit values in the YAML. It changes speed only, never results: the executor config is **not** part of `config_hash`. | answered 2026-09-21: **D-351** (accepted; revisit if the stage-2/3 grid shapes differ) |
| P-37 | "Dirty" means uncommitted **tracked** changes | T10b (c). `registry.writer.code_version` returns `<sha>-dirty` when `git status --porcelain --untracked-files=no` is non-empty. An untracked new file (e.g. a new YAML under `configs/`) therefore does not mark the checkout dirty, although it could change a result. Counting untracked files would mark almost every working session dirty (scratch files, reports). | Confirm tracked-only, or count untracked files under `configs/` and `src/` as dirty too. | answered 2026-09-21: **D-352** (**changed**: untracked files under `src/` or `configs/` count as dirty; elsewhere they do not) |
| P-38 | A futures parity run has no quantity step | T10b §3 / D-347, D-329. `run_backtest` exempts futures from `parity_qty_step` (futures are sized in contracts, D-329), but `validate_config` refuses **every** `tradingview` config without it, because a pipeline config has no futures flag yet (T04d is not started). A futures parity run would therefore be refused at config level. | Leave it until futures exist (T04d/P-02) and decide the flag then, or add a `futures` marker to the pipeline config now. | answered 2026-09-21: **D-353** (leave it; T04d adds the flag and the exemption) |
